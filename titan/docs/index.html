Titan docs

Titan is a native macOS terminal built on libghostty. It runs shells, Claude Code sessions and agents like pi side by side, with a browser they can drive and actions you can script.

Install

The latest release is a disk image, signed with a Developer ID and notarized by Apple. Open it and drag Titan to Applications.

  • macOS 26 (Tahoe) on Apple Silicon.
  • Claude Code for Claude panes. Without it, shells work as usual.
  • Titan checks for updates once a day and installs them from the tab bar.

Set it up

  1. Install an agent. Claude Code for Claude panes, and pi or any other agent you like for shells.
  2. Open the config with ⌘,. It's ~/.config/titan/config, with every setting written out and commented on first launch. Titan reads your Ghostty config first, so your font and theme carry over.
  3. Save. Titan applies changes within a second. A line it can't read shows in a bar with its line number.

To let agents open panes and drive Titan, set remote-control = true. The config builder writes a starting file for you.

Agents

Use Titan's own Claude pane, the claude CLI you already know, or another coding agent such as pi or Codex. Each one runs in a pane, can open panes and drive the browser beside it, and stays out of the panes that aren't its own.

Claude Code as a conversation

The same claude you have installed, with your settings, CLAUDE.md, skills and MCP servers, drawn as a feed with its own composer, model picker and context ring. Titan gives it its browser and pane tools as an MCP server, mcp__titan__*.

Uses your Claude Code login. There's no API key to paste into Titan.

zsh · ~/code/pomodoro
pomodoro ❯ claude
╭──────────────────────────────────────╮
│ ✻ Welcome to Claude Code             │
╰──────────────────────────────────────╯
  mcp: titan · browser_*, titan_do, titan_panes
> open the timer in the browser beside me

Prefer the TUI? Type claude

In a Titan shell, claude starts with Titan's hooks and tools added for that run only, never written to your settings. The tab shows when it's working or waiting, the Mac stays awake while it works, and it gets the browser and titan_do tools.

With several Claude accounts, the folder picks the account, or claude --account Work does.

π · ~/code/pomodoro
pomodoro ❯ pi
Start the dev server beside you with titan, open it in the
titan browser and click Break.
$ titan do new_split direction=right command="npm run dev"
$ titan browser navigate url=http://localhost:4173/
$ titan browser click ref=e3
Done.

pi works as it is

pi needs no plugin and no MCP setup. In a Titan shell it runs titan do, titan panes and titan browser with its bash tool, and finds them from titan actions. Its status shows on the tab from the escapes pi already sends.

Titan knows pi when it sees it, even renamed to pi by node, and keeps it to the panes it opened.

zsh · ~/code/pomodoro
pomodoro ❯ codex
$ titan actions
new_split direction=right|down [command=CMD] [folder=DIR]
read_pane pane=ID [lines=N]
titan browser <tool>: navigate, snapshot, click, type…

Codex, OpenCode, Gemini, Aider…

Any agent that can run a shell command can drive Titan the same way. Titan recognises Codex, OpenCode, Gemini, Aider, Amp, Goose, Crush and Cursor's agent by their process, or by AI_AGENT in their environment, and gives them the same pane limits as Claude.

The Claude pane

⌘N starts a Claude Code session in a folder you pick, drawn as a conversation with an input box of its own. It runs Claude Code in its structured stream mode, so replies, tool calls and their output arrive as messages instead of a scraped screen.

Send while it works
↩ sends at once, and Claude takes the message in at the running turn's next step. ⌥↩ queues it for when the turn ends instead.
Run what it suggests
Shell code blocks in a reply get Run, Run in a shell and Copy. Output streams in under the block. Nothing runs without the click.
See what changed
/diff and /git open a side pane with every file changed since the session started, plus git status, recent commits and stashes.
Every path is a link
File paths and URLs in the feed are clickable. A file opens beside the pane at its line, in a built-in viewer or your $EDITOR.
Pages and diagrams, live
HTML and SVG files Claude writes show up in the conversation as live pages. A mermaid block is drawn as a diagram, in the theme's colours.
A worktree each
⇧⌘N starts a session in a git worktree of its own, so two sessions can work on one repository without stepping on each other.
Model, effort, context
A model picker, an effort slider and a ring for how full the context window is. Permission modes run from asking every time to YOLO.
@ and /
@ fuzzy-finds files to mention. / lists the commands and skills installed for that session, with their descriptions.
Attach anything
Paste or drop images and files into a conversation, or drop them on a tab: a Claude session attaches them, a shell types their paths.
Know which session needs you
Tabs show whether their sessions are working, done or waiting on you. ⌘J jumps to the one that's waiting; hover a tab to see what each session is doing.

Fork & handoff

Two ways to take a conversation somewhere new without losing the one you're in. Each new session opens with a line back to where it came from: Forked from “…” or Handed off from “…”. Click it to bring the parent forward, or resume it if it's closed.

/fork [note]
Opens a new session with this one's whole history, as a conversation of its own, so it can try another approach while the parent carries on unchanged. The note, if you give one, waits in its composer.
Fork from Here
On any reply in the feed: a new session with the history up to that reply, for going back to a point before things went sideways.
/handoff [goal]
The session writes the opening message for a fresh one with only what matters for the goal: decisions, where the work stands, files, what failed, next steps. It opens in a new tab with the same folder, worktree, account, model, effort and permission mode, the message in its composer to edit before sending, plus a pointer to the old transcript for anything left out.
Compact ahead
When a turn ends past compact-ahead percent of the context window (60 by default; Settings › While it works), a copy of the conversation is compacted in the background while you keep working, and the session moves onto it at its next pause. The context ring pulses while it runs. compact-ahead = 0 leaves compacting to Claude Code.
Export as Markdown
Export Conversation as Markdown… and Copy Conversation as Markdown in the palette: prompts and replies in full, each tool call one line, no tool output.

The terminal

libghostty inside
The same VT core as Ghostty, drawn with Metal. Improvements upstream arrive as a rebuild, not a rewrite.
Sessions outlive the window
Shells and Claude sessions run in titan-ptyd, a small daemon, so quitting or updating Titan doesn't stop them. Reopen it and they're where you left them.
Tabs and splits
⌘D and ⇧⌘D split, ⇧⌘↩ expands a pane, and a grip shows on the divider as you drag it. Drag panes onto tabs, tabs out into windows. ⌘E shows every tab and its panes.
Recipes
Saved setups of shells and a browser in the config. They ask for what they need, a branch or a port, then open everything beside the pane you're in.
Images in the shell
The Kitty graphics protocol: kitty icat, yazi and ranger previews, chafa, image.nvim. titan diagram draws a Mermaid file right in the shell.
What's still running
A dev server an agent backgrounded, a nohup from a pane you closed: Running in Background finds them, with their ports, and stops them.
More than one Claude account
Map folders to Claude accounts and each session opens under the right one, its history kept apart. Continue a session under the other account in one click.

Runs sessions for you
Starts Claude sessions in your projects, each in a tab of its own, gives them tasks and more instructions, reads what they did, stops them, and reports back; several at once when a request splits.
Knows Titan
Answers how-to questions from Titan's manual and changelog, and runs Titan's commands for you. It needs no remote-control.
A map of the work
Above the conversation, folders and sessions as linked nodes, signals running to those at work, the ones waiting on you in red.
Conversations of its own
Each named in a few words, kept between launches, archived once inactive for 72 hours. On Haiku, so it's quick.

    Its own browser, and only that
    
          
    An agent drives the browser pane beside the pane it runs in, not another conversation's. Agents' browser panes keep cookies apart from yours, so an agent never browses signed in as you.
    
          
    Known by where it started
    
          
    Titan reads which pane an agent belongs to from the agent's own process, not from what a request claims, so pointing TITAN_PANE at another pane gains nothing.
    
          
    A log of what it did
    
          
    A pane an agent types into or reads shows a badge for a moment, and Show Remote Control Log lists the last 200 requests: who, what, which pane, and what you said.

    FAQ
    
        
    
          
    Can I use pi or Codex instead of Claude?
    
          
    Yes. Run them in a Titan shell. They drive Titan with the titan command (titan do, titan panes, titan browser), and Titan keeps them to their own panes as it does Claude. The Claude pane itself is for Claude Code.
    
          
    Can agents type into my shells?
    
          
    Not without asking. They can use the panes they open themselves and the ones you grant; for any other shell, Titan asks you first, and you can allow it once or for that pane. It's all off until you set remote-control = true.
    
          
    Does it need an API key?
    
          
    No. Titan runs the Claude Code that's installed, so sessions use the account it's signed in with and count against that plan as usual. pi and other agents use whatever they're set up with.
    
          
    Does it change how Claude Code behaves?
    
          
    Barely. It's the same CLI with your settings, skills and MCP servers. Titan adds a short note to the system prompt so Claude knows that pages show up in the feed, how to write paths that link, and, when you turn it on, that it can open panes.
    
          
    Where are my conversations?
    
          
    Where Claude Code keeps them, in ~/.claude/projects. Titan reads them for its history list and to resume sessions, and they work in the plain claude TUI as well.
    
          
    Why only macOS?
    
          
    Titan is a native Mac app: SwiftUI and AppKit for the window, Metal for drawing, Liquid Glass from macOS 26. Its terminal core, libghostty, runs elsewhere, but everything around it is written for the Mac. There are no plans for Linux or Windows.
    
          
    Where do I send feedback?
    
          
    Titan is a personal project and I'd like to hear what you think. Open an issue on the releases repo: what works, what doesn't, what you'd want next.
